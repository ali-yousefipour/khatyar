# نشست زندهٔ بی‌سیم و افکت‌های صوتی

## مسیر واقعی اجرا

محدودیت بی‌سیم به حضور فعال، **اجباری و مستقل از تنظیم قدیمی `radio_limit_to_shift`** است. فقط سطح‌های عددی ۱ تا ۴ استثنا دارند. همهٔ کاربران سطح ۵ تا ۹، حتی با دسترسی مدیریتی (`is_admin=1`)، باید ورود ثبت‌شدهٔ باز در `staff_attendance` داشته باشند و پس از خروج امکان دریافت/ارسال صوت ندارند. عنوان سمت و دسترسی مدیریت پنل موجب استثنا نمی‌شود؛ کنترل در هر درخواست API صدا مجدد انجام می‌شود. گزینهٔ قدیمی قابل خاموش‌کردن در پنل حذف شده و درخواست خاموش‌کردن از API مدیریتی رد می‌شود. کلاینت در پاسخ `403` پیام واضح برای ثبت حضور نمایش می‌دهد.

- پنل اصلی: آیتم «مرکز بی‌سیم» ← `RadioCenter` ← `RadioLiveTab` / `RadioArchiveTab` در `php/tools/panel_source.jsx`؛ مرورگر خروجی `php/app/assets/panel.bundle.js` را اجرا می‌کند.
- صفحهٔ مدیریت مستقل: `php/app/radio-admin.html` و `php/app/radio-admin.js`؛ مسیر قدیمی نیز از همان API مدیریت استفاده می‌کند.
- API مدیریت: `php/app/radio-admin-api.php?op=monitor` برای زنده و `op=archive` برای آرشیو؛ تنظیمات کانال در همان فایل هستند.
- اندروید: `mobile/src/screens/RadioScreen.js` ← `mobile/src/radio/RadioContext.js` ← `php/app/radio-api-v2.php`، عملیات `channels`, `poll`, `poll-all`, `responsible-recent`, `settings`, `take`, `send`, `release`.
- دریافت پس‌زمینه و افکت‌ها از **منبع canonical** در `mobile/plugins/khatyar-radio-native/` ساخته می‌شوند. `withKhatyarRadio.js` آن‌ها را هنگام Expo prebuild به پروژهٔ Android کپی می‌کند. فایل‌های تولیدیِ دارای تغییر محلی کاربر در `mobile/android/` نباید برای اعمال این تغییر reset یا بازنویسی شوند؛ CI پروژهٔ تمیز را از منبع canonical می‌سازد.

## علت بازپخش تاریخچه

در اندروید، شناسهٔ کانال قبل از پایان دریافت cursor تازه تغییر می‌کرد؛ effect/timer جدید می‌توانست با cursor کانال قبلی درخواست دهد. همچنین شناسهٔ کانال به‌تنهایی برای رد پاسخ دیررس در تغییر سریع A→B→A کافی نبود. پنل اصلی از `last_message_id` فهرست کانالِ بارگذاری‌شده در گذشته استفاده می‌کرد و صفحهٔ مستقل مدیریت از `after=0` شروع می‌کرد. این‌ها مرز قابل اعتماد «از این لحظه» نبودند.

## رفتار اصلاح‌شده

1. آغاز ورود به کانال، روشن‌کردن، تغییر شنود همهٔ کانال‌ها یا بازگشت به foreground یک نسل نشست تازه ایجاد می‌کند. صف/صدای قبلی لغو و دریافت خودکار تا همگام‌سازی متوقف می‌شود.
2. `GET ...?op=poll&channel_id=N&initialize=1` یا `op=poll-all&initialize=1` فقط `{messages:[],last_message_id:...}` برمی‌گرداند. عضویت کانال یا مجوز شنود همه **قبل** از محاسبهٔ cursor بررسی می‌شود. پارامتر افزوده است؛ قرارداد قبلی بدون initialize حفظ شده است.
3. API مدیریت نیز `op=monitor&channel_id=N&initialize=1` را می‌پذیرد. پخش زندهٔ هر دو پنل از snapshot تازه شروع می‌شود، نه از فهرست قدیمی یا صفر.
4. پس از موفقیت، فقط پیام‌های با ID بزرگ‌تر از cursor نشست دریافت/پخش می‌شوند. پاسخ‌ها، دانلودهای صدا، callbackهای پخش و تنظیمات قدیمی با شناسهٔ نسل کنترل می‌شوند. شکست همگام‌سازی به معنای پخش تاریخچه نیست؛ دریافت متوقف و خطا نمایش داده می‌شود.
5. سرویس native نیز شروع خود را با initialize انجام می‌دهد. تغییر کانال، کاربر، حالت شنود یا روشن‌کردن، نسخهٔ نشست native را تغییر می‌دهد. پاسخ poll و callbackهای MediaPlayer متعلق به نسخهٔ قبلی رد می‌شوند. توقف صریح، enabled را در تنظیمات سرویس خاموش می‌کند تا سرویس قدیمی خودکار برنگردد.
6. تاریخچه حذف نمی‌شود. پخش دستی سه پیام اخیر **مسئولان** در اندروید و تب آرشیو پنل حفظ می‌شوند. مسئولان همان فیلتر قبلی API با level بین ۱ تا ۵ هستند؛ این تغییر سیاست فرستنده‌ها را عوض نمی‌کند. انتخاب کانال/بازهٔ آرشیو نیز پاسخ دیررس قبلی را نمایش نمی‌دهد و صدای قبلی متوقف می‌شود.
7. مسدودشدن autoplay توسط مرورگر در پنل اصلی خطای قابل مشاهده و دکمهٔ «فعال‌کردن صدا / تلاش مجدد» دارد؛ پیام ناموفق برای تلاش دستی حفظ می‌شود، نه اینکه بی‌صدا از صف حذف شود.

مرز شنود لحظهٔ موفقیت snapshot سرور است. پیام‌های قبل از آن برای پخش دستی در تاریخچه‌اند. این تغییر ارسال/قفل PTT، مدت مجاز صحبت، قوانین عضویت منطقه/سمت یا مجوز شنود همه را گسترش نمی‌دهد.

## افکت‌ها

`RadioSfxPlayer.java` یک موتور PCM کم‌حجم با صف تک‌رشته‌ای است. صدای آغاز دریافت ۷۰ میلی‌ثانیه و پایان دریافت ۸۵ میلی‌ثانیه، نویز باند‌محدودِ کوتاه با افت سریع شبیه باز/بسته‌شدن squelch است. تأیید PTT حدود ۶۰، roger حدود ۹۰ و پایان محدودیت حدود ۱۱۰ میلی‌ثانیه است؛ لایه‌های هشدار و هیس طولانی حذف شده‌اند. دامنهٔ نمونه‌ها محدود، شروع/پایان نرم و افکت‌های native در foreground/background یکسان‌اند. خود موتور افکت، ولوم سیستم را به حداکثر تغییر نمی‌دهد؛ تنظیم/تقویت صدای گفتار موجود موضوع جداگانه‌ای است.

تأیید PTT پیش از شروع ضبط پخش می‌شود تا داخل پیام ضبط نشود. در نبود native، fallback صوتی کوتاه و کم‌حجم استفاده می‌شود. کیفیت ادراکی و بلندی واقعی هنوز باید روی گوشی و بی‌سیم/بلندگوی هدف شنیده و تأیید شود؛ آزمون سیگنال جای شنیدن روی دستگاه را نمی‌گیرد.

## آزمون و انتشار

```sh
cd php
bash tools/build_panel_bundle.sh
php tests/radio_live_test.php
node tests/radio_admin_live_test.cjs
node tests/radio_panel_live_test.cjs
cd ../mobile
node scripts/test-radio-live.cjs
node scripts/test-radio-sfx.cjs
npm run validate:babel
npx expo export --platform android --output-dir ../.build-temp/radio-android-export
```

آزمون اندروید با منبع قبلی به‌درستی شکست خورد و با اصلاحات موفق شد. آزمون‌ها مرز زنده، عدم بازپخش، پخش دستی، تغییر سریع A→B→A، پاسخ دیررس، شکست initialize، شنود همه، retry مرورگر و هفت پروفایل PCM را بررسی می‌کنند. آزمون PCM با javac/java و بدون دستگاه، طول/دامنه/انرژی/DC/شروع نرم را می‌سنجد؛ کامپایل native واقعی در workflow رسمی Android انجام می‌شود. آزمون‌های PHP/JS از داده و سرویس آزمایشی استفاده می‌کنند و مجوز/صدای دستگاه واقعی را تأیید نمی‌کنند.

نسخهٔ برنامه تغییر نمی‌کند. برای اصلاح بخش اندروید باید APK تازه حاوی این منابع نصب شود؛ انتشار PHP به‌تنهایی اپ نصب‌شده را عوض نمی‌کند. انتشار و بررسی HTTP، ساخت APK، نصب روی گوشی و آزمون واقعی دو کاربر چهار مرحلهٔ مستقل‌اند.
