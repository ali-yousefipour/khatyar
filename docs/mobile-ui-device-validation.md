# اعتبارسنجی عملی UI/UX اندروید خطیار — ماتریس پذیرش انتشار

**تاریخ تهیه:** ۲۰۲۶-۱۱-۲۱  
**نسخه منبع:** ۲.۰.۱۰؛ پیش از ساخت یا انتشار هر APK، SHA و نسخه را دوباره از main و `app.config.js` تأیید کنید.

> این سند، برنامه آزمون دستگاه است و نتیجه آزمون نیست. از داخل GitHub Actions تنها Parse/Babel/Expo JS bundle قابل تأیید بوده است؛ TalkBack، رندر native و دسترسی‌های سرور با حساب نقش واقعی هنوز باید عملی اجرا شوند.

## دستگاه و شرایط آزمون

- گوشی Android با عرض منطقی حدود ۳۶۰dp و ناوبری حرکتی، یک گوشی ۴۱۲dp و یک نمایشگر بزرگ / تبلت.
- برای هر مسیر اصلی، اندازه فونت سیستم **۱۰۰٪، ۱۲۵٪، ۱۵۰٪ و ۲۰۰٪**. یک بار نیز **Display Size بزرگ**، کیبورد Gboard فارسی و انگلیسی، جهت عمودی و حالت تاریک/روشن را بررسی کنید.
- TalkBack روشن: عنوان صفحه، نام و وضعیت انتخاب، جهت حرکت فوکوس، دکمه برگشت و اعلان خطای فرم بدون وابستگی به رنگ قابل فهم باشد.
- جهت RTL را در متن فارسی/تاریخ شمسی/پلاک ایران حفظ کنید؛ ارقام و محدوده زمان در ورودی‌ها جابه‌جا نشوند.
- از حساب آزمایشی و داده بدون اطلاعات شخصی استفاده کنید. از تصویر فیش حقوق واقعی یا شکایات در artifact عمومی GitHub استفاده نکنید.

## اعتبارسنجی مجوزها

۱. فهرست `/api/my/app-items` را برای هر نقش آزمایشی با منو و مسیرهای واقعی `App.js` تطبیق دهید؛ **منو معیار مجوز نیست** و API باید مستقل deny کند.  
۲. ابتدا نقش مجاز، سپس بدون بستن برنامه نقش را در سرور تغییر دهید؛ بعد از refresh نشست، صفحه قبلی نباید نمایش داده شود.  
۳. کاربر A را خارج، کاربر B با دسترسی کمتر را وارد کنید؛ cache یا پاسخ دیرهنگام کاربر A نباید باعث نمایش یا ذخیره داده شود.  
۴. بازه شیفت و محدودیت بی‌سیم باید روی endpoint، نه فقط UI، آزمایش شود.  
۵. بدون حساب‌های مجاز و محیط آزمایشی این مراحل «اجراشده» علامت نخورند.

## عملکرد، شبکه و خروجی

- cold start و warm start، سرعت دریافت اولین صفحه، زمان ایجاد گزارش، تعداد درخواست‌های تکراری و مصرف RAM/CPU را روی حداقل دو دستگاه ثبت کنید؛ اندازه‌گیری از روی سورس قابل استناد نیست.
- در قطع شبکه، وضعیت درخواست، صف، خطای قابل فهم و بازیابی بدون دوبار ارسال را بررسی کنید.
- پروژه باید `Project Integrity`، `Mobile Regression Isolation` و `Mobile Reliability QA` شامل `expo export --platform android` را با SHA مشترک بگذراند.
- انتشار APK امضاشده تنها پس از موفقیت build release و تأیید دستی smoke روی دستگاه مجاز است.

## ثبت شواهد

برای هر مورد، مدل دستگاه، نسخه Android، fontScale، display size، نقش آزمایشی، SHA، نتیجه واقعی، URL لاگ CI (در صورت وجود) و باگ قابل بازتولید ثبت شود. وضعیت پیش‌فرض همه موارد این سند **تأییدنشده روی دستگاه** است.
