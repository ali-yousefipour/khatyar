# مستند فنی محاسبه کارکرد، تقویم و تعطیلات خطیار

> این سند مرجع توسعه‌دهندگان برای منطق محاسبه کارکرد نیروها است. هر تغییر آینده در محاسبه تردد، شیفت، جمعه‌کاری، تعطیل‌کاری یا تقویم باید با این سند سازگار باشد و در صورت تغییر قاعده، ابتدا همین سند به‌روزرسانی شود.

## 1. اصل معماری

منبع واحد تشخیص وضعیت روز در منطق کارکرد، `IranCalendar` است. هیچ بخش جدیدی نباید تعطیلی را با یک لیست ثابت، فایل ثابت سالانه یا منبع مستقل محاسبه کند.

منابع وضعیت روز:

- روز هفته: محاسبه الگوریتمی از تاریخ جلالی.
- تعطیلی رسمی و مناسبت‌های تقویم: داده تقویم رسمی دریافت‌شده و cache‌شده توسط `IranCalendar`.
- تعطیلی دستی: رکوردهای جدول `holidays` که توسط ادمین ثبت می‌شوند.
- وضعیت نهایی تعطیلی: ترکیب تعطیلی رسمی و تعطیلی دستی.

فایل اصلی موتور کارکرد:

- `php/lib/ShiftCalc.php`

فایل تقویم:

- `php/lib/IranCalendar.php`

گزارش‌های تردد باید از همین موتور استفاده کنند و نباید منطق مستقل برای جمعه/تعطیل داشته باشند.

## 2. تقویم و به‌روزرسانی

`IranCalendar` برای هر سال جلالی داده‌های تقویمی را دریافت و در مسیر cache تقویم نگهداری می‌کند. cache باعث می‌شود در هر درخواست، سرویس خارجی فراخوانی نشود.

چرخه فعلی:

1. سال مورد نیاز مشخص می‌شود.
2. اگر cache معتبر وجود داشته باشد، همان داده استفاده می‌شود.
3. در صورت منقضی شدن cache، تقویم از سرویس رسمی پشتیبان فعلی دریافت می‌شود.
4. داده دریافت‌شده در cache سال ذخیره می‌شود.
5. اگر سرویس موقتاً در دسترس نباشد و cache قبلی وجود داشته باشد، cache قبلی استفاده می‌شود.
6. روزهای هفته مستقل از سرویس خارجی و از روی تاریخ محاسبه می‌شوند.
7. تعطیلات دستی ادمین در زمان خواندن تقویم با داده رسمی ادغام می‌شوند.

مدت اعتبار cache فعلی: ۲۴ ساعت.

### نکته توسعه‌ای

تقویم سال‌های آینده نباید با یک آرایه ثابت در JavaScript یا PHP پیاده‌سازی شود. برای سالی که داده رسمی هنوز در cache نیست، سیستم باید تلاش کند داده آن سال را از منبع تقویم دریافت کند.

برای پایداری بیشتر، در صورت توسعه بعدی می‌توان job زمان‌بندی‌شده برای sync سال جاری و سال آینده اضافه کرد؛ اما این job نباید منطق محاسبه کارکرد را از `IranCalendar` جدا کند.

## 3. API مرکزی تقویم

تمام اجزای UI و گزارش باید در نهایت به API مرکزی تقویم متصل باشند. هدف API مرکزی این است که DatePicker، گزارش‌ها، مدیریت تعطیلات و محاسبه کارکرد برداشت متفاوتی از تقویم نداشته باشند.

مسیر مورد انتظار:

- `/api/calendar`

این API باید اطلاعات روزهای سال، روز هفته، وضعیت تعطیلی رسمی، وضعیت تعطیلی دستی، عنوان مناسبت و منبع داده را بر اساس `IranCalendar` ارائه کند.

اگر API یا UI جدیدی برای تقویم اضافه شد، نباید مستقیماً به سرویس تقویم خارجی متصل شود.

## 4. تعطیلی دستی ادمین

ادمین می‌تواند تاریخ‌هایی را که در تقویم رسمی وجود ندارند، به‌صورت دستی تعطیل اعلام کند.

رکورد دستی حداقل شامل:

- تاریخ جلالی
- عنوان تعطیلی

باشد.

تعطیلی دستی برای محاسبه کارکرد معتبر است.

مثال:

- شنبه عادی + تعطیلی دستی + ۸ ساعت کار → ۸ ساعت تعطیل‌کاری.
- پنجشنبه عادی + تعطیلی دستی + ۶ ساعت کار → ۶ ساعت تعطیل‌کاری.
- جمعه + تعطیلی دستی + ۸ ساعت کار → ۸ ساعت جمعه‌کاری و صفر تعطیل‌کاری.

## 5. قاعده اصلی جمعه‌کاری و تعطیل‌کاری

جمعه و تعطیلی دو ویژگی قابل تشخیص برای روز هستند، اما در **محاسبه نوع کارکرد، جمعه اولویت دارد**.

قاعده قطعی:

| وضعیت روز | جمعه‌کاری | تعطیل‌کاری |
|---|---:|---:|
| روز عادی | ۰ | ۰ |
| جمعه عادی | کل کارکرد روز | ۰ |
| تعطیل رسمی غیرجمعه | ۰ | کل کارکرد روز |
| تعطیلی دستی ادمین غیرجمعه | ۰ | کل کارکرد روز |
| جمعه + تعطیل رسمی/مناسبت | کل کارکرد روز | ۰ |
| جمعه + تعطیلی دستی ادمین | کل کارکرد روز | ۰ |

بنابراین **هیچ دقیقه‌ای نباید هم‌زمان در جمعه‌کاری و تعطیل‌کاری ثبت شود**.

در عین حال، در نمایش گزارش می‌توان وضعیت تعطیلی رسمی یا دستی روز جمعه را برای اطلاع کاربر نشان داد؛ حذف تعطیل‌کاری به معنی حذف اطلاعات تقویمی نیست.

## 6. پیاده‌سازی قاعده در ShiftCalc

`ShiftCalc::calendarDay()` باید وضعیت روز را از `IranCalendar::day()` دریافت کند.

`ShiftCalc::isFriday()` باید فقط بر اساس محاسبه روز هفته عمل کند.

در `classifyDay` منطق باید معادل این باشد:

```text
isHoliday = officialHoliday OR manualHoliday OR fallbackHoliday
isFriday  = calendar weekday is Friday

fridayWork  = isFriday ? worked : 0
holidayWork = (isHoliday AND NOT isFriday) ? worked : 0
```

پارامتر `fallbackHoliday` فقط برای سازگاری با callerهای قدیمی است و نباید باعث شود تعطیلی دستی یا رسمی از بین برود.

فیلدهای استاندارد خروجی:

- `is_friday`
- `is_holiday`
- `is_official_holiday`
- `is_manual_holiday` در داده تقویم
- `holiday_title`
- `holiday_source`
- `friday_work`
- `holiday_work`

فیلدهای legacy مانند `friday` و `holiday` در صورت نیاز برای سازگاری نگه داشته می‌شوند، اما مقدار آنها باید از همان `friday_work` و `holiday_work` حاصل شود.

## 7. محاسبه دقایق کارکرد

مبنای محاسبه، sessionهای ورود و خروج ثبت‌شده برای نیرو است.

به‌صورت کلی:

```text
worked = مجموع دقایق sessionهای معتبر ورود/خروج
```

برای session بازِ روز جاری، در صورت مجاز بودن منطق جاری، زمان فعلی به‌عنوان انتهای موقت استفاده می‌شود.

زمان‌های شیفت و بازه‌های مجاز ورود/خروج توسط تنظیمات همان شیفت تعیین می‌شوند.

## 8. کارکرد مورد انتظار

`expected` از نوع شیفت و تنظیمات روز به دست می‌آید.

منطق کلی:

- شیفت `floating`: مقدار `float_minutes`.
- شیفت `advanced`: segmentهای همان روز.
- شیفت `rotating`: segment چرخه مربوط به تاریخ.
- شیفت‌های معمولی: segmentهای `weekly` مربوط به روز هفته.
- اگر `day_config.duty_min` وجود داشته باشد، این مقدار بر segmentهای معمول اولویت دارد.
- در نوع `auto`، روزهای تعطیل/جمعه‌ای که در duty عادی لحاظ نمی‌شوند، expected آن روز صفر است؛ در روز کاری عادی مقدار پیش‌فرض فعلی ۴۵۳ دقیقه است مگر تنظیم دیگری وجود داشته باشد.

## 9. اضافه‌کاری و کسری

در حالت auto:

```text
rawExtra = max(0, worked - expected)
overtime = min(rawExtra, roleOtCap)
surplus = max(0, rawExtra - roleOtCap)
shortage = max(0, expected - min(worked, expected))
```

سقف اضافه‌کاری می‌تواند از `auto_ot_cap_min` بیاید و در نبود آن، سقف پیش‌فرض نقش استفاده می‌شود.

در حالت‌های غیر auto، اضافه‌کاری بر اساس `worked - expected` و محدودیت روزانه شیفت محاسبه می‌شود.

هر تغییر آینده در سقف‌ها باید مستند شود؛ این مقادیر بخشی از منطق کسب‌وکار هستند.

## 10. شب‌کاری

دقایق شب‌کاری از هم‌پوشانی session با بازه شب محاسبه می‌شود.

بازه پیش‌فرض:

- شروع: `22:00`
- پایان: `06:00`

تنظیمات شیفت می‌توانند این بازه را تغییر دهند. اگر `night_calc` غیرفعال باشد، خروجی شب‌کاری صفر می‌شود.

## 11. دیرکرد و تعجیل خروج

در شیفت‌های segment-based:

- دیرکرد ورود با مقایسه اولین ورود با بازه مجاز شروع segment محاسبه می‌شود.
- تعجیل خروج با مقایسه خروج با بازه مجاز پایان آخرین segment محاسبه می‌شود.

برای شیفت floating منطق segment-based اعمال نمی‌شود.

## 12. گزارش روزانه تردد

گزارش‌های زیر باید از `IranCalendar` و `ShiftCalc` استفاده کنند:

- `php/app/api/admin-attendance-report-fast.php`
- `php/app/api/admin-attendance-report-safe.php`

گزارش روزانه باید حداقل بتواند این موارد را نمایش دهد:

- تاریخ جلالی
- روز هفته
- جمعه بودن
- تعطیل رسمی بودن
- تعطیل دستی بودن
- عنوان مناسبت
- منبع تقویم
- کارکرد
- جمعه‌کاری
- تعطیل‌کاری
- اضافه‌کاری
- کسری
- شب‌کاری

در جمعه‌ای که تعطیل رسمی یا دستی نیز هست، ستون تعطیلی می‌تواند وضعیت تعطیلی را نشان دهد، اما مقدار **تعطیل‌کاری باید صفر** باشد.

## 13. گزارش کارکرد ماهانه

گزارش ماهانه نباید فقط به اطلاعات روزانه اکتفا کند. باید جمع کل دو شاخص زیر را به‌صورت مستقل ارائه کند:

1. **جمعه‌کاری** — مجموع `friday_work` روزهای ماه.
2. **تعطیل‌کاری** — مجموع `holiday_work` روزهای ماه.

فرمول:

```text
monthlyFridayWork  = Σ daily.friday_work
monthlyHolidayWork = Σ daily.holiday_work
```

این دو مقدار نباید با هم ادغام شوند.

اگر روزی جمعه و تعطیل باشد، تمام کارکرد آن روز فقط به `monthlyFridayWork` اضافه می‌شود.

اگر روزی تعطیل دستی غیرجمعه باشد، تمام کارکرد آن روز به `monthlyHolidayWork` اضافه می‌شود.

پنل مدیریت باید این دو شاخص را به‌عنوان **دو ستون/کارت مجزا** نمایش دهد، نه صرفاً به‌عنوان فیلدهای گزارش روزانه.

## 14. DatePicker

DatePicker باید اطلاعات تعطیلات و مناسبت‌ها را از API مرکزی دریافت کند و نباید به فایل static مخصوص یک سال یا repository خارجی وابسته باشد.

ویژگی‌های لازم:

- پشتیبانی از سال‌های آینده.
- نمایش روز هفته.
- تشخیص تعطیل رسمی.
- تشخیص تعطیل دستی.
- نمایش عنوان مناسبت/تعطیلی.
- استفاده از cache آخرین داده معتبر در صورت خطای موقت شبکه.

روز هفته باید حتی بدون دسترسی شبکه قابل محاسبه باشد.

## 15. مدیریت تعطیلات در پنل

پنل مدیریت تعطیلات باید امکان‌های زیر را داشته باشد:

- مشاهده تعطیلات سال.
- انتخاب تاریخ جلالی.
- ثبت عنوان تعطیلی دستی.
- افزودن تعطیلی.
- حذف تعطیلی دستی.
- دریافت/به‌روزرسانی داده تقویم رسمی.

APIهای فعلی مدیریت تعطیلات در صورت حفظ معماری موجود باید با `IranCalendar` سازگار بمانند و نباید یک منبع تقویم دوم ایجاد کنند.

## 16. اصل جلوگیری از چندمنبعی شدن

موارد زیر ممنوع است:

- تعریف آرایه ثابت تعطیلات در JavaScript برای سال خاص.
- استفاده از یک جدول مستقل برای تعطیلی در گزارش و `IranCalendar` در محاسبه.
- تشخیص جمعه با یک mapping متفاوت در هر فایل.
- محاسبه تعطیل‌کاری مستقل در frontend.
- جمع‌زدن `friday` و `holiday` به‌عنوان یک شاخص واحد.
- استفاده از منبع خارجی تقویم در یک جزء UI و منبع دیگری در backend بدون هماهنگی با `IranCalendar`.

هر قابلیت جدید باید از `IranCalendar` → `ShiftCalc` → API گزارش → UI پیروی کند.

## خلاصه مرجع سریع

```text
Calendar source = IranCalendar
Weekday source  = algorithmic Jalali weekday
Official holiday = IranCalendar official data
Manual holiday   = holidays table merged by IranCalendar

Friday priority:
    Friday + official holiday -> Friday work only
    Friday + manual holiday   -> Friday work only

Non-Friday:
    official holiday -> holiday work
    manual holiday   -> holiday work

No double counting:
    holiday_work = worked only when is_holiday AND NOT is_friday
    friday_work  = worked only when is_friday

Monthly:
    Friday work  = SUM(daily friday_work)
    Holiday work = SUM(daily holiday_work)
```
