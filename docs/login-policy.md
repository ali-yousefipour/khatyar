# روش ورود سایت و اندروید

مرجع تنظیمات، مقادیر JSON در `app_settings` است: `web_login_method` و `app_login_method` با مقادیر `password`، `sms_otp` یا `bale_otp`. در نبود تنظیم، وب مانند رفتار قبلی `sms_otp` و اندروید `password` است. مقدار نامعتبر یا خطای خواندن تنظیمات نباید به ورود با رمز تبدیل شود.

- `GET /api/session/web-login-config` و `GET /api/session/app-login-config`: پاسخ عمومی فقط شامل `method` است.
- `POST /api/session/start` و alias قدیمی `/api/auth/login`: ورود با رمز فقط وقتی روش همان نوع کلاینت `password` باشد.
- وب: `POST /api/session/otp-request` و `/api/session/otp-verify`.
- اندروید: `POST /api/session/app-login-request` و `/api/session/app-login-verify`.

در درخواست کد، `username` لازم است؛ شماره و مقصد ارسال فقط از اطلاعات ثبت‌شدهٔ سرور می‌آیند. تأیید کد، `username`، `code` و `device_id` می‌گیرد. نوع کلاینت در مسیر OTP از خود route تعیین می‌شود و با بدنه قابل تغییر نیست. اندروید همان سیگنال‌های امنیتی ورود با رمز را می‌فرستد.

بله از `BaleBot::findChatForUser` و `sendMessage` و پیامک از `Sms::send` استفاده می‌کند. نبود اتصال بله به ارسال پیامکی جایگزین نمی‌شود. محدودیت درخواست موجود (۶۰ ثانیه و پنج درخواست در ساعت برای هر کاربر)، انقضای سه‌دقیقه‌ای، سقف پنج تلاش و مصرف شرطی یک‌باره اعمال می‌شوند. hash کد به نوع کلاینت و روش تنظیم‌شده وابسته است؛ تغییر روش، کد روش قبلی را نامعتبر می‌کند. جدول همان `login_otp` موجود است و migration تازه لازم نیست.

هر دو روش اندروید از handler مشترک برای مجوز، تعمیرات، تکمیل هویت، محدودیت‌های امنیتی و اتصال تک‌دستگاهی استفاده می‌کنند. OTP مجوز تعویض خودکار دستگاه نیست. قطع نشست مدیر همچنان `revoked_at` را مقدار می‌دهد و ورود بعدی می‌تواند اتصال را تجدید کند. علت خطای عملیاتی باقی‌مانده پس از قطع نشست، با این اصلاح به‌تنهایی اثبات یا رفع‌شده فرض نمی‌شود.

پنل، وب‌اپ و موبایل روش واقعی را دریافت می‌کنند. نسخهٔ نصب‌شدهٔ ۱.۵.۱۳ از قبل endpointهای اندروید را فراخوانی می‌کند و با نصب بک‌اند کامل، تنظیمات را می‌گیرد. تغییر جدید موبایل فقط fallback رمز روی 404 را حذف می‌کند و برای رسیدن آن تغییر به گوشی، ساخت APK جدید لازم است. شمارهٔ نسخه تغییر نکرده است. کدهای OTP درخواست‌شده پیش از انتشار hash جدید باید دوباره درخواست شوند (با رعایت فاصلهٔ ارسال).

آزمون محلی:

```sh
php php/tests/login_policy_test.php
node php/tests/login_policy_ui_test.cjs
node php/tests/web_auth_test.cjs
cd php && bash ./tools/build_panel_bundle.sh
node --check app/assets/panel.bundle.js
```

آزمون PHP handlerهای واقعی را با Db و سرویس ارسال شبیه‌سازی‌شده اجرا می‌کند؛ تست UI تابع واقعی تنظیمات موبایل و فرم/درخواست‌های وب‌اپ را اجرا می‌کند. این‌ها تأیید MySQL زنده، تحویل پیامک/بله، APK روی گوشی یا رفع رخداد همهٔ نیروها نیستند. workflow انتشار، endpointهای عمومی تنظیمات و رد درخواست OTP بدون نام کاربری را نیز بررسی می‌کند.
