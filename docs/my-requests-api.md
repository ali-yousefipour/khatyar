# فهرست درخواست‌های پرسنل

تب «درخواست‌های من» در اپ موبایل در `mobile/src/screens/RequestsScreen.js`، تابع `MyRequests`، با درخواست `GET /my/requests` بارگذاری می‌شود. مسیریاب PHP آن را به `GET /api/my/requests` در `php/lib/routes.php` وصل می‌کند و رکوردهای کاربر جاری را از جدول `requests` می‌خواند.

## ساخت جدول

نصاب `php/app/install.php` فایل `php/db/mysql_schema.sql` را اجرا می‌کند. تعریف جدول `requests` باید هم در این schema وجود داشته باشد و هم با DDL استفاده‌شده در `php/db/upgrade_full_standalone.sql` سازگار بماند.

برای نصب‌هایی که جدول ندارند، مسیرهای ثبت و دریافت درخواست ابتدا `_ensure_requests_table()` را اجرا می‌کنند. این تابع فقط در صورت نبود جدول آن را می‌سازد؛ دادهٔ جدول موجود را تغییر نمی‌دهد. حساب دیتابیس برنامه باید مجوز `CREATE TABLE` داشته باشد تا نصب قدیمیِ بدون جدول با اولین درخواست ترمیم شود.

## قرارداد پاسخ

`GET /api/my/requests` پاسخ را به‌صورت آرایه‌ای از حداکثر ۱۰۰ درخواست، مرتب‌شده از جدید به قدیم، برمی‌گرداند. اگر ستون اختیاری `substitute_user_id` وجود داشته باشد، نام نیروی جایگزین نیز همراه نتیجه است؛ در غیر این صورت query بدون آن ستون اجرا می‌شود.

خطای اجرای SQL در سرور ثبت می‌شود و در حالت عادی پاسخ 500 عمومی برمی‌گردد. در صورت تکرار خطا پس از ایجاد جدول، لاگ PHP باید برای خطای SQL ستون‌های جدول بررسی شود؛ وضعیت schema دیتابیس میزبان از روی مخزن قابل تأیید نیست.
