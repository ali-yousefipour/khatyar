# یکسان‌سازی Android و Web — ۱۴۰۵/۰۶/۰۴

## تغییرات این مرحله

### ثبت تصویر
- تصویر محل ایستگاه و تصویر تابلو در Android فقط از دوربین گوشی گرفته می‌شوند.
- هیچ مسیر انتخاب تصویر از Gallery در این جریان وجود ندارد.
- در Web نیز ورودی فایل ایستگاه پنهان شده و دکمه اختصاصی دوربین با `getUserMedia` استفاده می‌شود؛ فایل نهایی JPEG است.
- دقت GPS در ثبت موقعیت ایستگاه همچنان حداکثر ۲۰ متر است و کنترل Backend نیز برقرار می‌ماند.

### رفع نمایش ناقص تصاویر
- پیش‌نمایش سلفی و تصویر ثبت‌شده با ارتفاع محدود و `resizeMode=contain` بازطراحی شد.
- صفحه پیش‌نمایش در Android دارای `ScrollView` است تا در نمایشگرهای کوچک، تصویر یا دکمه‌های تأیید زیر صفحه نروند.
- پیش‌نمایش Web نیز دارای محدودیت ارتفاع و نسبت ابعاد امن است.

### همسان‌سازی رابط Web
- ترتیب امکانات اصلی Web با منوی امکانات Android هماهنگ شده است.
- runtime جدید `web-android-parity-v2.js` برای اصلاح چینش قدیمی و بازسازی کارت‌های امکانات استفاده می‌شود.
- این runtime در `app.html` توسط workflow خودکار درج می‌شود تا در تغییرات بعدی، مرجع اجرای parity از قلم نیفتد.

## تست الزامی بعدی
1. Android: صحت‌سنجی حضور و مشاهده کامل سلفی در نمایشگر کوچک.
2. Android: ثبت تصویر محل/تابلو و اطمینان از نبود Gallery.
3. Web موبایل: بازکردن دوربین پشت و ثبت هر دو تصویر.
4. Web: بررسی همه صفحات اصلی در برابر ترتیب Android.
5. Production: بررسی cache/PWA و بارگذاری نسخه جدید پس از deploy.

- مقایسه صفحه‌به‌صفحه تمام Screenهای Android با routeهای Web و ثبت اختلاف‌های جزئی هر صفحه.
- تست دستگاه واقعی Android 9 و Android 14/15 برای دوربین و preview.
- اجرای build release و تست regression پس از build.
