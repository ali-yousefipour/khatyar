# بازطراحی رابط پنل مدیریتی — ۲۰۲۶/۱۰/۲۰

## دامنه و مسیر واقعی

هدف، یکدست‌کردن ظاهر و بهبود استفاده از پنل فارسی/RTL در موبایل و دسکتاپ است. وب‌اپ پرسنل، نسخهٔ محصول، دادهٔ عملیاتی، قرارداد API، محاسبات PHP و کوئری‌های MySQL تغییر نکرده‌اند.

مبنای شروع: شاخهٔ `main`، کامیت `e3ee9e3e8d77db11a72ef6732602fcb682cd7ada`؛ پس از fetch، اختلاف با `origin/main` صفر بود. فایل‌های محلی خارج از Git حفظ و از staging کنار گذاشته شدند.

مصرف‌کنندهٔ واقعی `php/app/panel.html` است و `assets/panel.bundle.css` و bundle ساخته‌شده از `php/tools/panel_source.jsx` را بارگذاری می‌کند. گروه‌بندی `SECTIONS` در `App` شامل ۵۹ آیتم در هفت گروه است: داشبورد و پایش، عملیات میدانی، تاکسی و تاکسیران، گزارش‌ها، منابع انسانی، ارتباطات و مدیریت سامانه. صفحات از منوی سایت زنده، به‌ترتیب گروه‌ها باز شدند؛ نمایش حالت بارگذاری، تأیید دریافت کامل داده تلقی نشده است. ورود به لاگ، خطای قطعی متغیر تعریف‌نشده ایجاد کرد و ادامهٔ پیمایش به تنظیمات نیازمند بارگذاری مجدد بود.

مسیر گزارش تردد: منوی `attreport` → `AttendanceReport` → `db.attendanceReport(userId,from,to)` → `GET /api/admin/attendance-report?user_id=…&from=…&to=…` → route مقدم در `php/app/index.php` → `php/app/api/admin-attendance-report-owned.php` → خواندن `staff_attendance` و منطق موجود. این مسیر و خروجی آن تغییر نکرده‌اند.

## تغییرات

- `php/tools/panel_source.jsx`: جستجوی صفحات مجاز با پشتیبانی از تفاوت ی/ک فارسی و عربی، جستجوی گروه، حالت بدون نتیجه، نمایش مسیر صفحه، نام و وضعیت دسترس‌پذیر منوی موبایل، بستن با Escape و لینک رفتن به محتوا. جایگزینی ۱۰ جدول بدون محفظهٔ اسکرول با `ResponsiveTable`؛ سلول‌ها، فیلترها و handlerها حفظ شده‌اند.
- همان منبع: رفع `visibleUsers is not defined` در `Logs` با استفاده از فهرست موجود `users`؛ این خطا هنگام بازکردن صفحه، کل درخت React را خالی می‌کرد.
- `php/app/assets/panel.bundle.css`: رنگ‌ها و فاصله‌های مشترک، منوی کم‌تراکم، فرم‌ها، دکمه‌ها، تب‌ها، جدول‌ها، داشبورد، ورود، نمایش باریک، focus و reduced-motion؛ هماهنگی بصری ماژول‌های موجود مدارس و شکایات؛ حفظ اسکرول و چاپ جدول‌ها.
- `php/app/panel.html`: فقط cache-key فایل‌های CSS و JS؛ شماره نسخه تغییر نکرده است.
- `php/app/assets/panel.bundle.js`: خروجی build رسمی همان منبع.
- `php/tests/panel_navigation_ui_test.cjs`: تست رفتاری روی bundle واقعی برای فهرست صفحات، جستجو، نام‌گذاری فارسی/عربی، گروه، نبود نتیجه، محدودیت مجوز، انتخاب صفحه، Escape، رندر لاگ و حفظ سلول/ویژگی جدول.
- `.github/workflows/project-integrity.yml`: اجرای تست جدید در مرحلهٔ موجود بررسی پنل.

## اعتبارسنجی محلی

فرمان ساخت از پوشهٔ `php`:

```sh
bash ./tools/build_panel_bundle.sh
```

build موفق شد؛ بررسی‌های داخلی آن برای سازگاری bundle با مرورگر و ماژول‌های منوی فعلی نیز موفق بودند.

فرمان‌های موفق از ریشه:

```sh
node --check php/app/assets/panel.bundle.js
node php/tests/panel_navigation_ui_test.cjs
node php/tests/work_finalization_ui_test.cjs
node php/tests/org_regions_ui_test.cjs
node php/tests/seniority_ui_test.cjs
node php/tests/seniority_deployment_test.cjs
node php/tests/org_chart_deployment_test.cjs
git diff --check
```

پیش‌نمایش محلی از همان HTML/CSS/bundle با پاسخ‌های آزمایشی فقط‌خواندنی اجرا شد؛ نشست یا دادهٔ خصوصی تولیدی به آن منتقل نشد. وابستگی‌های vendor محلی کامل نبودند و برای پیش‌نمایش از مسیرهای وب استفاده شد. خطای اولیهٔ Chart و شکل ناقص پاسخ تنظیمات بی‌سیم، محدودیت fixture بودند و با تکمیل محیط پیش‌نمایش برطرف شدند؛ API تولیدی به‌خاطر fixture تغییر نکرد.

داشبورد، گزارش تردد و کاربران در موبایل و دسکتاپ مشاهده شدند. کاربران، لاگ، تنظیمات، فرم‌ساز، ارسال پیامک و مرکز گزارش‌ها در عرض ۳۹۰ باز شدند؛ عرض سند از عرض viewport بیشتر نبود. مرکز گزارش‌ها در عرض ۳۲۰ نیز بدون سرریز سند مشاهده شد. عرض ۱۴۴۰ برای دسکتاپ بررسی شد. جدول کاربران محفظهٔ اسکرول مستقل دارد. انتخاب گزارش تردد، بسته‌شدن منوی موبایل و حفظ فیلترهای موجود مشاهده شد.

صفحهٔ ورود نیز جداگانه در پیش‌نمایش بررسی شد. در نخستین بررسی عرض ۳۹۰، track ضمنی Grid باعث عرض سند ۴۳۶ شد؛ با تعریف `grid-template-columns:minmax(0,1fr)` اصلاح شد. بررسی مجدد: عرض viewport و سند هر دو ۳۹۰ و عرض کارت ورود ۳۵۸ پیکسل بود. cache-key CSS برای این اصلاح تکمیلی به `20261020.admin-workspace2` تغییر کرد.

## حدود شواهد
