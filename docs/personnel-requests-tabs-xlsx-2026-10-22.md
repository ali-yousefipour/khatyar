# درخواست‌های پرسنل: تب‌ها، تقویم شمسی و XLSX

## مسیر و رفتار

کلید داخلی منو و مجوز `requests` ثابت است؛ عنوان صفحه، منو، فهرست دسترسی و فایل خروجی «درخواست‌های پرسنل» شد. `AdminRequests` در `php/tools/panel_source.jsx` سه تب «در انتظار بررسی»، «تأییدشده» و «ردشده» دارد. تب اول پیش‌فرض است. تغییر تب درخواست GET جدید با status مربوط می‌فرستد، انتخاب‌ها را پاک و پاسخ قبلی را نامعتبر می‌کند؛ کلیک مجدد روی تب فعال فهرست را پاک نمی‌کند.

فیلترهای «ثبت از/تا» از `JDate` موجود استفاده می‌کنند: نمایش و انتخاب فارسی/شمسی است؛ مقدار ارسالی همان ISO میلادی مورد انتظار API و ستون `created_at` باقی می‌ماند. تاریخ خود مرخصی یا تردد با تاریخ ثبت اشتباه گرفته نمی‌شود.

خروجی همان GET `/api/admin/requests/export` با همان فیلترها و تب فعال است، اما اکنون XLSX واقعی از `XlsxWriter` می‌سازد. عنوان، شمار ردیف‌ها، وضعیت و بازهٔ ثبت در سربرگ، راست‌به‌چپ، سرستون رنگی، ردیف‌های راه‌راه، عرض ستون‌ها، ارتفاع متناسب توضیحات، فیلتر، تثبیت سرستون و چاپ افقی فعال‌اند. متن کاربر literal است و به فرمول Excel تبدیل نمی‌شود. سقف موجود ۵۰۰۰ ردیف حفظ و در رابط اعلام شده است.

در تب ردشده دکمهٔ «تأیید مجدد» و انتخاب گروهی وجود دارد. همان مودال بررسی مرخصی قبل از تأیید نمایش داده می‌شود. API مدیریتی گذار rejected→approved را همراه pending→approved می‌پذیرد؛ وضعیت قبلی در UPDATE مقایسه می‌شود. قفل کاربر، سیاست کاری، سهمیه، مهلت مطابق تنظیم سیاست، همپوشانی با درخواست فعال و اثر تردد/جایگزینی دوباره کنترل می‌شوند. گذار approved→approved همچنان رد می‌شود. هیچ درخواست واقعی برای QA تغییر وضعیت داده نمی‌شود.

## فایل‌ها

- `php/tools/panel_source.jsx`: عنوان، تب‌ها، تقویم، دانلود XLSX و تأیید مجدد؛ `php/app/assets/panel.bundle.js` خروجی build؛ `php/app/panel.html` کلید cache.
- `php/lib/routes.php`: خروجی XLSX و گذار اتمی تأیید مجدد با کنترل همپوشانی.
- `php/lib/XlsxWriter.php`: API اختیاری `setRowHeight`؛ رفتار خروجی‌های قدیمی بدون فراخوانی آن ثابت است.
- `php/tests/request_export_fixture.php` و `php/tests/request_export_xlsx_test.cjs`: ساخت و بازخوانی ZIP واقعی با دادهٔ ساختگی، styles/RTL/سربرگ/فیلتر/چاپ و ایمنی فرمول.
- `php/tests/request_report_ui_test.cjs`، `php/tests/request_report_test.php` و `php/tests/work_policy_requests_test.php`: سه تب، دو تقویم، مسیر تأیید مجدد، وضعیت قبلی و رد همپوشانی.
- `.github/workflows/project-integrity.yml`: اجرای آزمون XLSX جدید.

## اعتبارسنجی

ساخت رسمی از پوشه `php`: `bash ./tools/build_panel_bundle.sh`، سپس `node --check php/app/assets/panel.bundle.js` و PHP lint برای routes/XlsxWriter. آزمون‌های درخواست و رابط/جزئیات/ناوبری و XLSX جدید اجرا شدند. آزمون‌های XLSX سنوات و شیفت چرخشی نیز برای حفظ رفتار نویسندهٔ مشترک اجرا شدند.

در PHP محلی افزونه‌های موجود `php_zip.dll` و `php_mbstring.dll` با گزینه‌های `-d` برای آزمون XLSX فعال شدند؛ تنظیم PHP یا وابستگی پروژه تغییر نکرد. نمونهٔ غیرعملیاتی `.build-temp/request-report-professional.xlsx` ساخته شد. فایل در Excel رومیزی باز نشده است؛ ساختار OOXML و قالب‌بندی آن به‌صورت خودکار بررسی شده‌اند. نتیجهٔ workflow، تطبیق HTTP و بررسی خواندنی UI سایت جدا در گزارش پایان اعلام می‌شوند.
