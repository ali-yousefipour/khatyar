# حقوق ماهانهٔ شرکت و فیش A5

## مسیر اجرای واقعی

- پنل: گروه «منابع انسانی» ← «بارگذاری فیش حقوقی» ← `SalarySlipsAdmin` در `php/tools/panel_source.jsx`؛ خروجی مرورگر `php/app/assets/panel.bundle.js` است.
- سه تب مستقل: «فیش‌های پیوستی» (قابلیت قبلی PDF/تصویر)، «بارگزاری فایل حقوق از شرکت» و «فیشهای حقوقی پرسنل».
- اندروید: مسیر موجود `SalarySlips` در `mobile/App.js` به `SalarySlipsScreen` در `mobile/src/screens/RequestScreens.js` وصل است. تب جدید `CompanyPayrollHistory` بدون تغییر مسیر یا نسخه اضافه می‌شود.
- فایل‌های قدیمی پیوستی و جدول `user_salary_slips` دست‌نخورده‌اند. حقوق ماهانه با تردد، محاسبات حقوق سامانه، سنوات یا مشخصات کاربر ادغام نمی‌شود.

## قرارداد فایل و اعداد

نمونهٔ شرکت، شیت اول با ۴۳ ستون معنادار، عنوان در سطر اول و سربرگ دوطبقه در سطرهای دوم و سوم دارد. شیت‌های بعدی خروجی بانکی‌اند و دوباره وارد نمی‌شوند. عنوان باید شامل سال و نام ماه انتخاب‌شده باشد. تغییر ستون‌ها خطاست، نه مجوز جابجا کردن خودکار مبالغ. XLS/XLSM/CSV پذیرفته نمی‌شوند؛ سقف XLSX ده مگابایت، محتوای بازشده چهل مگابایت و تعداد سطرهای ورودی پنج هزار است. فرمول‌ها اجرا نمی‌شوند؛ نتیجهٔ ذخیره‌شدهٔ Excel خوانده می‌شود. نبود نتیجهٔ ذخیره‌شده خطاست و فایل باید مجدداً در Excel محاسبه و ذخیره شود.

مبالغ **ریال** هستند. رشتهٔ عددی منبع در JSON نگهداری می‌شود؛ مبلغ حقوق، بیمه، مالیات، سنوات، کارکرد یا اضافه‌کاری از قوانین سامانه دوباره محاسبه نمی‌شود. فیلد `net` برای جمع‌های گزارش `DECIMAL(20,6)` است. کارت‌ها مبالغ را به ریال کامل نشان می‌دهند؛ جزئیات تا شش رقم اعشار و قالب چاپ طبق Format گزارش اکسس است. مقدار خالی با صفر تفاوت دارد. اختلاف بیش از دو ریال در «مزایا منهای کسورات در برابر خالص» هشدار است و مبلغ شرکت را تغییر نمی‌دهد. این داده‌ها **اعلام شرکت** هستند، نه اثبات واریز بانکی.

نمونهٔ شهریور ۱۴۰۵ ارسالی محلی با ۱۰۳ ردیف پرسنلی خوانده شد؛ هیچ مغایرت جمع مزایا/کسورات/خالص دیده نشد. یک ردیف شمارهٔ پرسنلی صفر دارد اما کد ملی دارد. فایل حاوی اطلاعات شخصی در Git قرار نمی‌گیرد و به‌صورت خودکار روی تولید وارد نمی‌شود.

## تطبیق، پیش‌نمایش و ثبت

1. فایل و ماه انتخاب، پیش‌نمایش دریافت و ردیف‌ها بررسی شوند.
2. تطبیق فقط با کد ملی یا شمارهٔ پرسنلی یکتا است. کد ملی عددی به ده رقم کامل می‌شود؛ شمارهٔ پرسنلی صفر، شناسهٔ معتبر نیست. نام به‌تنهایی مبنای اتصال نیست. تعارض دو شناسه، چند حساب یا چند ردیف برای یک حساب، خودکار منتشر نمی‌شود.
3. ردیف نامنطبق یا متعارض نگهداری می‌شود؛ فقط مدیر آن را می‌بیند. دکمهٔ «تطبیق دستی» حساب مقصد را با تأیید صریح مدیر متصل و `mapped_by/mapped_at` را ثبت می‌کند. اتصال به کاربری که در همان ماه ردیف دیگری دارد رد می‌شود.
4. ثبت دوبارهٔ ماه نیازمند تأیید جایگزینی است. کل فایل جدید جای نسخهٔ فعال را می‌گیرد، نه اینکه به حقوق قبلی اضافه شود. نسخه‌های قبلی حذف نمی‌شوند. تطبیق دستی نسخهٔ قبلی خودکار به نسخهٔ تازه منتقل نمی‌شود.
5. توکن HMAC پیش‌نمایش به هش فایل، ماه، نسخهٔ سرور، محتوای خوانده‌شده و تطبیق حساب‌ها متصل است. هنگام ثبت، فایل دوباره خوانده و کاربران/ماه داخل تراکنش قفل می‌شوند. تغییر نسخه یا تطبیق باعث 409 و لزوم پیش‌نمایش دوباره است. شکست ذخیره‌سازی rollback می‌شود؛ ارسال مجدد توکن قبلی پس از ثبت موفق قابل اعمال نیست.

## جدول‌ها و API

`Payroll::ensure()` سه جدول مستقل InnoDB را در اولین استفاده ایجاد می‌کند. SQL دستی لازم نیست؛ حساب دیتابیس باید مجوز CREATE TABLE داشته باشد:

- `payroll_periods`: ماه یکتا، batch فعال و revision؛ قفل اصلی برای هم‌زمانی ثبت و تطبیق.
- `payroll_batches`: سوابق فایل، هش SHA256، نام فایل، بارگذار و زمان؛ نسخهٔ قدیمی حفظ می‌شود.
- `payroll_rows`: سطر اکسل، حساب مقصد nullable، snapshot تمام ستون‌ها، هشدار و اطلاعات تطبیق دستی؛ هر حساب در هر batch حداکثر یک ردیف دارد.

تمام مسیرها در `php/lib/Payroll.php` ثبت و از `php/lib/routes.php` بارگذاری می‌شوند:

| مسیر | دسترسی و قرارداد |
| --- | --- |
| `POST /api/admin/payroll/import` | مدیر؛ multipart شامل `file`, `period_jy`, `period_jm`, `mode=preview/commit`؛ ثبت شامل `token` و برای جایگزینی `replace=1` |
| `GET /api/admin/payroll` | مدیر؛ `year`, `month`, `q`, `user_id`, `status=pending`, `page`؛ صفحه‌بندی ۵۰ ردیف و جمع همان فیلتر |
| `GET /api/admin/payroll/{id}` | مدیر؛ جزئیات snapshot نسخهٔ فعال |
| `PUT /api/admin/payroll/{id}/match` | مدیر؛ JSON با `user_id` و تأیید سمت UI |
| `GET /api/my/payroll` | نشست معتبر و مجوز `SalarySlips`؛ فقط حساب جاری، فیلتر ماه/سال و صفحه‌بندی |
| `GET /api/my/payroll/{id}` | همان مجوز؛ مالکیت در SQL کنترل می‌شود؛ ردیف دیگران یا نسخهٔ غیرفعال 404 |

پاسخ‌ها `private, no-store` هستند. اندروید نیز `noStore:true` دارد؛ خطای شبکه با حقوق قبلیِ کش‌شده پنهان نمی‌شود. API جدید لینک عمومی دائمی برای حقوق ساختاریافته ایجاد نمی‌کند. شمارهٔ حساب و اطلاعات کامل فقط در جزئیاتِ مجاز برگردانده می‌شوند.

## قالب چاپ اکسس

طبق تأیید کاربر، گزارش **«مرداد»** متصل به جدول **«شهریور»** و دارای عنوان شهریور ۱۴۰۵ مرجع است؛ گزارش دیگر «فیش حقوق» مرجع انتخاب‌شده نیست. فایل اکسس صرفاً به‌عنوان داده/قالب بررسی شده و ماکروهای آن اجرا نشده‌اند.

`php/app/assets/payroll-access-layout.json` شامل هندسهٔ واقعی کنترل‌ها بر حسب twip، عنوان‌ها، Format، وزن فونت و نشان شرکت استخراج‌شده از گزارش است؛ اطلاعات پرسنلی یا رکوردهای Access در آن نیست. `payrollSlipHtml` همان محل و اندازهٔ جعبه‌ها، سه ستون، نشان و امضاها را روی A5 افقی با حاشیهٔ ۵ میلی‌متر و عرض محتوای ۲۰۰ میلی‌متر بازتولید می‌کند. عنوان ماه پویاست. نام و اعداد HTML-escape می‌شوند. `payrollPrint` ابتدا پنجره را با کلیک کاربر باز می‌کند، سپس جزئیات مجاز و قالب را می‌گیرد و پس از آماده شدن فونت/تصویر چاپ می‌کند. مسدود بودن popup پیام خطا دارد.

برای همان شکل حروفِ مرجع، فونت **B Homa** باید روی رایانهٔ چاپ نصب باشد؛ فونت سیستم با مجوز نامشخص در مخزن کپی نشده است. در نبود آن، Vazirmatn/Tahoma جایگزین می‌شود؛ هندسه ثابت است ولی شکل حروف یکسان نیست. تنظیم چاپ: A5 افقی، مقیاس ۱۰۰٪، بدون header/footer مرورگر. هر فیش یک صفحه است. چاپ مبلغ اعلامی رسید بانکی تولید نمی‌کند.

## ساخت، آزمون و انتشار

```sh
cd php
bash tools/build_panel_bundle.sh
node --check app/assets/panel.bundle.js
php -l lib/Payroll.php
php tests/payroll_test.php
node tests/payroll_ui_test.cjs
cd ../mobile
npm run validate:babel
node scripts/test-company-payroll.cjs
npx expo export --platform android --output-dir ../.build-temp/payroll-android-export
```

PHP به ZipArchive، XMLReader، SimpleXML و mbstring نیاز دارد. آزمون‌ها از دادهٔ ساختگی استفاده می‌کنند و تطبیق/عدم افشای حساب دیگر، قالب/اعداد، هشدار مغایرت، تغییر ماه، پیش‌نمایش، جایگزینی، رد replay، تغییر تطبیق، rollback، مجوزها، UI و چاپ A5 را می‌سنجند. آزمون‌های تراکنش با Db آزمایشی هستند و جای آزمون MySQL واقعی را نمی‌گیرند. پیش از بهره‌برداری، یک ماه آزمایشی را با ادمین وارد کنید، ردیف نامنطبق و حساب دیگر را کنترل و یک چاپ واقعی بگیرید.

در بررسی محلی، PDF واقعی گزارش Access مشاهده شد و چاپ مرورگر با دادهٔ ساختگی به PDF تک‌صفحه‌ای A5 افقی (حدود ۲۱۰×۱۴۸ میلی‌متر) تبدیل و تصویر آن بازبینی شد. متن نمونه سرریز نداشت. فایل‌های آزمایشی حاوی دادهٔ شخصی در مخزن قرار نمی‌گیرند. این بررسی جای آزمون چاپگر فیزیکی و حساب‌های واقعی را نمی‌گیرد.

workflow `deploy-php.yml` کتابخانهٔ Payroll را از مسیر installer محافظت‌شده منتشر و آزمون‌های PHP/پنل را اجرا می‌کند. تب اندروید نیازمند ساخت و نصب APK حاوی منبع جدید است؛ انتشار PHP به‌تنهایی اپ نصب‌شده را تغییر نمی‌دهد. شمارهٔ نسخه در این تغییر عوض نمی‌شود.
