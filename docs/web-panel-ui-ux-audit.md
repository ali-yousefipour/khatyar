## زنجیره و سطح دسترسی

- `VIEWS` فقط نمای موردنظر را مشخص می‌کند؛ کد `can(key)` و فیلتر `menuSections` دسترسی ناوبری را اعمال می‌کنند. **مجوز مؤثر باید برای هر endpoint در PHP تأیید شود** و مخفی‌شدن گزینه منو کافی نیست.
- `php/app/index.php` مسیر API و صفحات عمومی را کنترل می‌کند؛ `php/lib/routes.php` و فایل‌های مسیر تخصصی باید در هر جریان جداگانه ردیابی شوند.
- فایل‌های مستقل مانند `school-service-admin.js`، `school-complaints-admin.js`، `work-report-default-placement-ui.js` و استایل‌های مربوطه در ممیزی یکپارچه بعدی باید به مدخل مرتبط متصل شوند.

## موارد باز و معیار ادامه

1. برای هر ۶۱ مدخل: تحلیل دسترسی واقعی، APIهای خواندن/نوشتن، حالت‌های بارگذاری/خطا، جدول‌ها، فرم‌ها، مودال‌ها و عکس در عرض‌های ۳۲۰ تا ۱۹۲۰.
2. شناسایی و شمارش مستقل ماژول‌های متصل به JS خارج از JSX و مسیرهای عمومی/وب‌اپ؛ تا آن زمان «همه صفحات» ادعا نشود.
3. آزمون تعاملی مرورگر شامل فوکوس، Escape، Tab، ارسال تکراری، شکست شبکه و برگشت به فرم.
4. اجرای Build واقعی پنل، PHP lint، تست‌های موجود و بررسی CI؛ بررسی HTTP هاست و نسخه فایل بعد از Deploy.
5. جمع‌آوری P0–P3 تنها با بازتولید و مستندکردن علت ریشه‌ای؛ از اعلام صفر برای کل پروژه اجتناب شود.

### محدوده پوشش و محدودیت

- **پوشش‌داده‌نشده و باقی‌مانده:** خروجی‌های XLSX کاملاً سمت مرورگر، دانلود مستقیم لینک‌های مستقل، ابزارهای PHP که بدون Fetch استفاده می‌شوند، وب‌اپ `app.html`، صفحات عمومی و پردازش‌های طولانی‌ای که زمان واقعی کار در کلاینت صرف می‌شود. برای هر کدام اتصال اختصاصی و آزمون لازم است.
- **آزمون:** `php/tests/panel_long_operation_progress_test.cjs` و اجرای آن در Workflow `deploy-php.yml` تعریف شده است؛ وضعیت موفقیت باید از اجرای همان Workflow تأیید شود.
- **ایمنی:** هیچ درخواست یا محاسبه‌ای تغییر داده نشده، URL و داده شخصی در لاگ جدید ذخیره نمی‌شوند. درصد فقط در صورت مقدار واقعی API مربوطه نمایش داده می‌شود.
