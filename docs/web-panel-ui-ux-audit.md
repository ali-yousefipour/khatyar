## زنجیره و سطح دسترسی

- `VIEWS` فقط نمای موردنظر را مشخص می‌کند؛ کد `can(key)` و فیلتر `menuSections` دسترسی ناوبری را اعمال می‌کنند. **مجوز مؤثر باید برای هر endpoint در PHP تأیید شود** و مخفی‌شدن گزینه منو کافی نیست.
- `php/app/index.php` مسیر API و صفحات عمومی را کنترل می‌کند؛ `php/lib/routes.php` و فایل‌های مسیر تخصصی باید در هر جریان جداگانه ردیابی شوند.
- فایل‌های مستقل مانند `school-service-admin.js`، `school-complaints-admin.js`، `work-report-default-placement-ui.js` و استایل‌های مربوطه در ممیزی یکپارچه بعدی باید به مدخل مرتبط متصل شوند.

## موارد باز و معیار ادامه

1. برای هر ۶۱ مدخل: تحلیل دسترسی واقعی، APIهای خواندن/نوشتن، حالت‌های بارگذاری/خطا، جدول‌ها، فرم‌ها، مودال‌ها و عکس در عرض‌های ۳۲۰ تا ۱۹۲۰.
2. شناسایی و شمارش مستقل ماژول‌های متصل به JS خارج از JSX و مسیرهای عمومی/وب‌اپ؛ تا آن زمان «همه صفحات» ادعا نشود.
3. آزمون تعاملی مرورگر شامل فوکوس، Escape، Tab، ارسال تکراری، شکست شبکه و برگشت به فرم.
4. اجرای Build واقعی پنل، PHP lint، تست‌های موجود و بررسی CI؛ بررسی HTTP هاست و نسخه فایل بعد از Deploy.
5. جمع‌آوری P0–P3 تنها با بازتولید و مستندکردن علت ریشه‌ای؛ از اعلام صفر برای کل پروژه اجتناب شود.

- **WEB-UX-018 (P1، PDF سمت مرورگر):** تابع ساخت PDF مستقل شکایات، تبدیل JPEG صفحات Canvas را به‌صورت ترتیبی با yield بین صفحات انجام می‌دهد تا UI بتواند لودینگ را به‌روزرسانی کند. API اختیاری `onProgress(completed,total)` برای تعداد صفحات واقعی به نمایشگر مشترک متصل شد؛ پس از آخرین صفحه مرحله «ساخت فایل نهایی» نمایش داده می‌شود، بدون درصد ساختگی. هندسه صفحات، محتوای پرونده و ساختار PDF حفظ شد.
- **WEB-UX-019 (P2، جدول):** هنگام خالی بودن نتایج پرونده‌های شکایات، پیام وضعیت خالی با `role=status` و `colSpan=9` جای خالی جدول را توضیح می‌دهد و روی موبایل نیز سبک مستقل دارد.
- **تست جدید:** `php/tests/school_complaints_wizard_pdf_test.cjs` قرارداد فوکوس و حالت خالی جدول را بررسی می‌کند و تولید واقعی PDF چندصفحه‌ای را با Canvas شبیه‌سازی‌شده، شمارش صفحات و فراخوانی دانلود اجرا می‌کند. این تست به gate انتشار اضافه شد.
- **نسخه فایل‌ها:** فایل JS/CSS شکایات پس از تکمیل اصلاحات تا `20261121.wizard5` در منبع React، Bundle و Portal همسان‌سازی شد و PDF در Shell و Portal به `20261121.7` ارتقا یافت. تست‌های نسخه به‌روز شدند؛ Workflow `School Complaints Regression` برای SHA `d7bffedb` موفق است. تأیید استقرار هاست مستقل و همچنان ضروری است.
- **دامنه باقی‌مانده:** این بهبودها جایگزین آزمون واقعی فرم‌ها و خروجی همه ۶۱ نما نیستند؛ سنجش performance حافظه و زمان، رفتار شبکه و هر ۷ عرض نمایشگر در مرورگر احرازشده همچنان مورد باز است.


## تکمیل تکمیلی مرحله سوم و چهارم — WEB-UX-020 تا WEB-UX-023 (۲۰۲۶-۱۱-۲۱)

### مرحله سوم: فرم‌ها، ویزاردها و مودال‌ها

- **WEB-UX-020 (P1 — جستجوی چندمنظوره ویزارد):** جستجوی مدرسه، شرکت و کاربر اختصاصی شکایات قبلاً صرفاً فهرست دکمه‌ها بود؛ با کلیدهای پیکان و کلیک بیرون رفتار کامل نداشت. `Lookup` اکنون دارای combobox با `aria-expanded`، `aria-controls`، `aria-autocomplete`، `aria-busy`، فهرست `role=listbox` و گزینه‌های `role=option` است. ArrowDown از فیلد به فهرست و ArrowUp/ArrowDown بین گزینه‌ها منتقل می‌کند، Escape فهرست را می‌بندد و کلیک بیرون نیز فهرست را می‌بندد. فوکوس هنگام بستن بدون بازکردن مجدد کنترل می‌شود. رنگ focus نتایج در CSS مشخص شده است.
- **WEB-UX-021 (P1 — Modal مشترک):** هنگام باز بودن بیش از یک مودال، handler سراسری Escape و Tab هر Modal می‌توانست هم‌زمان فعال شود. شرط فعال‌بودن dialog جلویی در منبع React و باندل اعمال شد؛ آزمون `php/tests/panel_shared_modal_focus_test.cjs` با وجود مودال بالاتر، عدم بسته‌شدن مودال زیرین را می‌سنجد.

### مرحله چهارم: جداول، گزارش‌ها و لودینگ

- **WEB-UX-022 (P1 — صحت خروجی Excel):** خروجی شکایات اکنون `total` را از نظر عدد صحیح امن، غیرمنفی بودن و تطبیق با ردیف‌های دریافتی اعتبارسنجی می‌کند؛ بیش از ۱۰ هزار ردیف را قبل از ساخت رد می‌کند؛ اگر API قبل از رسیدن به تعداد اعلام‌شده صفحه خالی بازگرداند، از تحویل فایل ناقص جلوگیری می‌کند. تبدیل ردیف‌ها در دسته‌های ۲۵۰تایی انجام می‌شود و در صورت وجود لودینگ مشترک، مرحله با تعداد ردیف واقعی و yield میان دسته‌ها نمایش داده می‌شود. خطای serializer و شبکه در `finally` لودینگ را می‌بندند. این پردازش هنوز نمی‌تواند درصد واقعی عملیات همگام `XLSX.writeFile` را گزارش دهد.
- **WEB-UX-023 (P2 — جدول و بازیابی خطا):** جدول پرونده‌ها دارای `caption` دسترس‌پذیر با تعداد نتایج و صفحه‌بندی با برچسب «صفحه X از Y» و `aria-live` است. در صورت شکست بارگذاری داشبورد، فهرست یا تنظیمات شکایات به‌جای نمایش لودینگ دائمی، پیام قابل‌بازیابی و دکمه «تلاش مجدد» ارائه می‌شود.
